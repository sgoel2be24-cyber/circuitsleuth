## High: completed inspections can be mutated through MCP

Locations: `backend/app/tools/mcp_server.py:38-44`, `backend/tests/test_mcp.py:72-76`, `frontend/src/pages/Workspace.tsx:30-38` at the reviewed commit.

Reproduced: MCP detection accepts a completed HTTP inspection, replaces candidates with SUSPECTED candidates, and retains its old report/status. Separately, source review shows an MCP report can leave the run created; opening it in the UI can trigger the REST auto-start path. That UI integration edge was not browser-reproduced.

Fix and acceptance: define one REST/MCP finalization contract; reject terminal mutators; ensure a finished MCP run opens without restarting; add cross-interface tests. Guard against stale whole-state writes when clients overlap; atomic file replacement alone is insufficient.

## High: adding a capture changes completed-run provenance

Locations: `backend/app/api/routes.py:470-488`, `frontend/src/pages/Workspace.tsx:101-107`.

Reproduced: adding view2 to a completed missing-view inspection changes its inputs while its report and events remain unchanged. The UI adds the capture before separately requesting rerun, so a rerun failure can leave the original inconsistent.

Fix and acceptance: clone/create the child before attaching the capture, preferably in one operation. Record parent, input hashes and capture event. Verify the original run's inputs/report/events are unchanged even when child creation or execution fails.

## Medium: clipped-glare mask expands valid pixels

Location: `backend/app/cv/detection.py:105-109`.

The valid mask is dilated despite the comment promising exclusion of clipped pixels and a halo. A 256x256 checkerboard with an otherwise unchanged 20x20 clipped-white patch produced candidate `[100,100,20,20]`, difference 0.4877 and mismatch 0.7549, without illumination-suspect classification. This proves an unnecessary candidate, not a falsely confirmed final defect.

Fix and acceptance: erode valid support, or dilate invalid support and invert. Add a clipped-glare regression; rerun the full benchmark to measure genuine-defect/recall effects before promoting the change.

## Medium: rejected review retains anomaly label

Locations: `backend/app/api/routes.py:507-512`, `frontend/src/pages/Report.tsx:77-91`.

Reproduced: rejected review produces CLEARED with `unclassified_surface_anomaly` and basis `operator review (rejected)`. The report renders the non-null anomaly label.

Fix and acceptance: clear the final label on rejection, or explicitly separate historical model prediction from the final human verdict. Verify the API response, saved report and UI agree for both accepted and rejected reviews.

## Medium: failed auto-start has no useful retry

Locations: `frontend/src/pages/Workspace.tsx:30-38,84`, `backend/app/api/routes.py:331-352`.

Source-established: the start guard is set before the request succeeds. A start failure can leave created state displayed as running; refreshing inspection state does not retry, and Stop has no task to cancel. A network-fault browser reproduction was not performed.

Fix and acceptance: reset the guard on failure, show an actionable error and Retry Start, and prevent duplicate concurrent starts. Test a failed request followed by a successful retry.

## Verification and limits
